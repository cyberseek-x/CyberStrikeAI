# 资产批量扫描执行配置设计

## 目标

在“资产库 → 创建扫描任务”弹窗中提供执行模式、专家角色和多资产并行数配置，避免所有资产任务固定使用单代理串行执行。

## 已确认交互

- 采用方案 A：在用户提示词上方新增一行任务配置区。
- 执行模式支持 `Eino 单代理（ADK）`、`Deep（DeepAgent）`、`Plan-Execute`、`Supervisor`。
- 专家角色列出系统当前已启用的角色，默认选择“信息收集”；角色已删除、停用或角色列表加载失败时回退到“信息收集”。
- 并行任务数范围为 1～8，默认 2。它只控制同时运行的资产子任务数，不改变单个资产内部的工具执行方式。
- 系统未启用多代理时，后三种多代理模式不可选择，并给出可理解的状态提示。
- 新配置只在“创建扫描任务”模式显示；“发送到对话”保持现有行为。
- 创建失败后保留弹窗和用户输入，便于修改后重试。

## 数据流

打开弹窗时，前端读取当前多代理启用状态并加载角色列表，随后初始化默认值：`agentMode=eino_single`、`role=信息收集`、`concurrency=2`。提交批量任务时，把三个字段与现有 `tasks`、`executeNow`、`projectId`、`scheduleMode=manual` 一并发送到 `/api/batch-tasks`。

后端继续使用现有批量队列：`agentMode` 和 `role` 决定每个子任务的代理编排与角色，`concurrency` 决定同一批次最多同时运行多少个资产任务。现有服务端规范化逻辑继续把并发限制在 1～8。

## 异常与兼容

- 多代理状态读取失败时采用保守策略，仅允许 Eino 单代理。
- 角色接口失败时仍保留“信息收集”选项，使任务请求保持确定性。
- 非法并行数在前端提交前限制到 1～8，服务端现有逻辑继续作为第二道校验。
- 不修改资产与批量队列的数据结构，不增加数据库迁移。

## 验收条件

1. 任务模式显示三项配置，对话模式隐藏三项配置。
2. 默认值为 Eino 单代理、信息收集、并行数 2。
3. 已启用角色可选择，停用角色不出现。
4. 多代理关闭时只能选择 Eino 单代理。
5. `/api/batch-tasks` 请求包含选中的 `agentMode`、`role`、`concurrency`。
6. 中英文界面均有完整、自然的文案。
