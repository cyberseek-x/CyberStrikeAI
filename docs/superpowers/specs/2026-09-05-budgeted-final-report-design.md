# 有时限的单代理收尾报告设计

## 背景

Eino 单代理目前以模型迭代次数作为主要终止条件。每轮可能调用多个工具，而工具耗时差异很大，因此轮次不能向用户提供稳定的完成时间。达到 `max_iterations` 时，Eino 直接返回 `exceeds max iterations`，现有处理路径把它作为失败展示，无法保证生成最终报告。

## 目标

1. 标准单代理调查阶段默认最多运行 12 分钟，报告阶段独立预留 3 分钟。
2. 调查达到时间或迭代上限时，自动切换为不挂载工具的报告生成阶段。
3. 报告阶段只使用已有轨迹与证据，不再调用工具。
4. 报告阶段失败时保留原始错误；用户主动停止仍按取消处理，不擅自继续运行。
5. 预算通过 `agent` 配置段调整，并兼容未配置的新旧配置文件。

## 非目标

- 本次不重做完整任务进度界面。
- 本次不为每个安全工具增加独立超时字段。
- 本次不改变 Deep、Supervisor 和 Plan-Execute 模式。
- 本次不自动继续用户主动取消的任务。

## 架构

新增一个小型预算解析模块，集中计算调查时限、报告时限和报告迭代次数。单代理处理器先用调查上下文运行原代理；当调查上下文超时或 Eino 达到迭代上限时，处理器保存模型可见轨迹，构造一个关闭 Skills、关闭工具搜索且角色工具为空的报告配置，然后在独立报告上下文中运行一次无工具代理。

Eino 运行错误处理器新增“迭代上限可恢复”开关。单代理调查阶段开启该开关，只发送“调查预算已用完”进度事件，不提前发送错误；其他模式保持现有错误行为。报告阶段关闭该开关，避免报告阶段再次超限时被误判为可恢复。

## 配置

```yaml
agent:
  max_iterations: 20
  task_timeout_minutes: 15
  finalization_reserved_minutes: 3
  finalization_max_iterations: 2
```

`task_timeout_minutes` 是总预算；调查预算为总预算减去报告预留时间。解析规则会保证调查和报告都至少有一分钟。未配置时采用 15/3/2。

## 状态与数据流

1. 任务进入 `running`。
2. 调查阶段按现有方式产生模型、工具和证据事件。
3. 正常得到最终文本时直接完成，不进入强制报告。
4. 达到调查时间或迭代上限时，发送 `forced_report_generation` 事件。
5. 保存并恢复最近模型可见轨迹，追加“只生成阶段性报告”的指令。
6. 用无工具配置运行报告阶段。
7. 报告成功则按现有 finalizer 交付；报告失败则沿用现有错误处理。

## 错误处理

- 用户停止：立即取消，保持“已取消”语义。
- 调查超时：转入报告阶段，不展示原始超时错误。
- 调查轮次用尽：转入报告阶段，不展示 `NodeRunError`。
- 报告超时或再次超限：展示明确错误并保留已有过程详情。
- 轨迹恢复失败：使用当前历史生成报告，并记录服务端日志。

## 测试

- 预算默认值、正常配置和异常配置的表格测试。
- 可恢复迭代上限只发进度、不发错误的测试。
- 非可恢复迭代上限保持原有错误事件的回归测试。
- 处理器阶段切换判定与无工具报告配置测试。
- 运行 `go test ./...` 和 `go build ./cmd/server`。
