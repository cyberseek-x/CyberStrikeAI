# 信息收集资产自动入库与七天查重设计

日期：2026-09-05  
状态：待用户复核  
目标分支：feat/budgeted-final-report

## 1. 背景

当前“信息收集”任务可以调用子域枚举、命令执行和项目事实工具，但没有强制调用 create_asset。因此，任务可能生成项目事实和报告，却没有把已验证端点写入资产库。现有资产表具备唯一去重键与 last_scan_at，但自由对话任务开始前不会主动查询这些记录，所以相似任务仍可能重复探测。

## 2. 目标

1. 将已验证端点按“域名或 IP + 端口 + 协议”写入资产库。
2. 对话绑定项目时，新资产自动绑定同一项目。
3. 同一项目中七天内已经扫描的端点复用现有结果，不重复主动探测。
4. 新发现、从未扫描、超过七天或用户明确要求重新扫描的端点允许扫描。
5. 最终报告展示本轮新增、更新、复用、重扫、跳过和失败数量。
6. 资产归档补偿阶段最多运行一次，避免无限循环和额外 Token 消耗。

## 3. 非目标

- 不从任意自然语言报告直接正则提取并静默入库。
- 不把历史 DNS、重定向地址、CDN 节点自动判定为业务资产。
- 不把 198.18.0.0/15 代理映射地址保存为真实公网 IP。
- 不改变用户明确发起“重新扫描”或“强制刷新”时的行为。

## 4. 方案比较

### 方案 A：仅加强提示词

实现简单，但模型仍可能忘记调用资产工具，不能保证落库。

### 方案 B：工具约束与一次性归档补偿（采用）

在提示词、工具行为和收尾检查三层约束资产落库。它不解析不可靠的报告文本，并能复用现有 MCP 执行证据。

### 方案 C：后端解析扫描文本

自动化程度高，但容易把无关域名、历史解析、VPN 映射或响应内容里的地址误存为资产，暂不采用。

## 5. 数据流

### 5.1 任务开始：项目资产预检

当请求使用“信息收集”角色或明确包含资产发现、暴露面、子域枚举等意图时：

1. 读取当前对话绑定的项目。
2. 查询项目资产库，建立端点索引。
3. 根据 last_scan_at 将端点分为：
   - fresh：七天内已扫描；
   - never：从未扫描；
   - stale：超过七天；
   - new：本轮新发现。
4. 将精简索引注入模型上下文，不把整份资产详情重复塞入上下文。

被动发现仍可用于查找新域名；对 fresh 端点跳过端口、HTTP 指纹和漏洞类主动探测。never、stale、new 进入正常验证。

### 5.2 调查阶段：即时入库

每个端点只有在至少获得一项可复核证据后才调用 create_asset，例如：

- DNS 得到有效地址；
- TCP 端口连通；
- HTTP/HTTPS 返回有效响应；
- 专用测绘工具返回带来源的记录。

create_asset 继续使用数据库唯一键去重：已有记录更新非空字段，不新建重复行。

### 5.3 项目自动绑定

create_asset 收到的 project_id 为空、且当前对话已经绑定项目时，由服务端从工具上下文注入当前项目 ID。显式传入其他项目仍受既有权限边界检查。

### 5.4 地址过滤

198.18.0.0/15 视为代理、VPN 或测试映射地址：

- 不写入资产 ip 字段；
- 如果对应域名本身已验证，可只保存域名端点；
- 映射现象写入项目事实或报告限制项；
- 公网 IP 必须来自可信 DNS 路径或实际连接证据。

其他回环、链路本地、组播和未指定地址同样不作为公网 IP 入库；私网地址仅在明确的内网评估任务中保存。

### 5.5 收尾检查与一次性归档补偿

信息收集结束时检查本轮 MCP 执行：

- 已成功调用 create_asset：直接进入报告。
- 已产生发现证据但没有资产写入：进入一次“资产归档阶段”。
- 归档阶段只开放 create_asset、query_assets 和必要的项目事实读取工具，不允许继续扫描。
- 归档阶段最多执行一次；失败后仍结束任务，但报告必须明确列出未入库原因，不得声称已保存。

### 5.6 七天查重和强制刷新

默认新鲜期为七天。判断条件以资产 last_scan_at 为准：

- now - last_scan_at 小于 7 天：复用；
- 空值或超过七天：允许扫描；
- 用户输入包含明确的重新扫描、强制刷新、忽略缓存语义：允许扫描并更新 last_scan_at。

只发现并入库但尚未完成扫描的资产，其 last_scan_at 为空，下次仍会进入扫描候选。

## 6. 最终报告

报告增加“资产处理统计”：

| 指标 | 含义 |
|---|---|
| 新增 | 本轮新建资产 |
| 更新 | 命中去重键并补充字段 |
| 复用 | 七天内已扫描，未重复主动探测 |
| 重扫 | 过期或用户强制刷新 |
| 跳过 | 证据不足或地址被过滤 |
| 失败 | 入库工具调用失败 |

每条资产结论标注证据来源与状态，不把“工具执行成功”等同于“发现已确认”。

## 7. 错误处理

- 资产工具不可用：停止归档补偿，在报告中显示配置问题。
- 单条资产参数无效：记录失败并继续处理其他候选。
- 项目权限不符：拒绝跨项目写入。
- 全部候选均被过滤：报告显示零新增，并列出过滤原因。
- 归档补偿再次没有资产调用：结束任务并显示“本轮未完成资产入库”，不再次循环。

## 8. 测试与验收

1. create_asset 在项目对话中自动补全 project_id。
2. 同一端点重复写入只更新一条记录。
3. 198.18.0.0/15 不作为公网 IP 入库，域名仍可单独保存。
4. 七天内资产被标记为复用，超过七天或从未扫描的资产进入扫描候选。
5. “重新扫描/强制刷新”绕过七天新鲜期。
6. 有发现但零资产写入时只触发一次归档补偿。
7. 最终报告统计与实际工具执行结果一致。
8. 全量 Go 测试通过，构建成功，服务重启后首页返回 HTTP 200。
9. 在副本上执行回滚，源码、二进制和运行状态恢复；正式运行目录保留优化版本。
